# Αξιολόγηση του SmartBeach

Υλικό για το κεφάλαιο «Αξιολόγηση» της πτυχιακής. Καλύπτει τρία επίπεδα:
**ορθότητα** (αυτόματα tests), **απόδοση** (load test) και **ευχρηστία** (SUS με πραγματικούς χρήστες).

---

## 1. Ορθότητα: αυτόματα tests

```bash
cd backend
pip install -r requirements-dev.txt
python -m pytest -v
```

Τα tests τρέχουν σε πραγματική MySQL/MariaDB, σε ξεχωριστή βάση `smartbeach_test`, και ελέγχουν:

| Αρχείο | Τι αποδεικνύει |
|---|---|
| `test_rules.py` | Επικάλυψη διαστημάτων, τιμολόγηση μισής/ολόκληρης μέρας, σεζόν, ωράριο |
| `test_auth.py` | Ο χρήστης δεν μπορεί να γίνει admin μόνος του· ο υποβιβασμός ισχύει αμέσως |
| `test_bookings.py` | Απόρριψη επικαλυπτόμενων κρατήσεων· η τιμή «παγώνει» στην κράτηση· οι ακυρώσεις δεν σβήνονται |
| `test_concurrency.py` | **20 ταυτόχρονες κρατήσεις στην ίδια θέση → ακριβώς 1 επιτυχία** |
| `test_filters.py` | Φίλτρα τύπου, τιμής, διαθεσιμότητας, απόστασης |
| `test_checkin_and_stats.py` | QR check-in, σωστοί υπολογισμοί εσόδων, πληρότητας και ποσοστών |
| `test_assistant.py` | Τα εργαλεία του AI βοηθού βλέπουν μόνο τα δεδομένα του χρήστη και δεν κάνουν κράτηση χωρίς επιβεβαίωση |

Το GitHub Actions (`.github/workflows/ci.yml`) τα τρέχει σε κάθε push με MySQL 8.

## 2. Απόδοση: load test (Locust)

```bash
cd backend
python -m scripts.seed_demo --reset          # ~11.000 κρατήσεις δοκιμαστικά
uvicorn app.main:app --port 8000 &
locust -f loadtest/locustfile.py --host http://localhost:8000 \
       --users 100 --spawn-rate 20 --run-time 2m --headless --csv loadtest/results
```

Το `loadtest/results_stats.csv` δίνει χρόνους απόκρισης (μέσος, p50, p95, p99) και αιτήματα/δευτ.
Στο τέλος, το SQL που υπάρχει στην αρχή του `locustfile.py` πρέπει να επιστρέφει **0 γραμμές**
(καμία διπλή κράτηση κάτω από φόρτο).

Ενδεικτική εκτέλεση σε laptop (50 χρήστες, 20 δευτ., MariaDB): 0 σφάλματα, διάμεσος χρόνος
απόκρισης ~8 ms για αναζήτηση, χάρτη και κράτηση, 0 διπλοκρατήσεις. Οι πιο αργές κλήσεις είναι
`/auth/register` και `/auth/login`, γιατί το bcrypt είναι **σκόπιμα** αργό (προστασία από brute force).

Πρόταση για πίνακα στην πτυχιακή: τρέξε με 25 / 50 / 100 / 200 χρήστες και σύγκρινε p95.

## 3. Ευχρηστία: System Usability Scale (SUS)

Το SUS είναι το πιο διαδεδομένο τυποποιημένο ερωτηματολόγιο ευχρηστίας (Brooke, 1996):
10 ερωτήσεις, κλίμακα 1–5, αποτέλεσμα 0–100. Πάνω από 68 θεωρείται πάνω από τον μέσο όρο.

### Διαδικασία (προτεινόμενη)

1. 10–15 συμμετέχοντες (φίλοι/συμφοιτητές· ιδανικά και 1–2 υπάλληλοι beach bar για τον ρόλο staff).
2. Κάθε συμμετέχων εκτελεί σενάρια **χωρίς βοήθεια**, ενώ καταγράφεις χρόνο και λάθη:
   - Σ1: «Κλείσε VIP ξαπλώστρα στην πρώτη σειρά για το πρώτο Σάββατο της σεζόν, απόγευμα.»
   - Σ2: «Άλλαξε την ώρα της κράτησης σε 15:00–20:00 και μετά δείξε το QR εισόδου.»
   - Σ3: «Βρες τη φθηνότερη παραλία με ελεύθερη θέση για την πρώτη Κυριακή της σεζόν, το πρωί.»
   - Σ4: «Ζήτα από τον βοηθό να σου βρει και να σου κλείσει μια θέση.»
   - Σ5 (staff/admin): «Κάνε check-in σε έναν πελάτη» / «Βρες ποιος μήνας είχε τα περισσότερα έσοδα.»
3. Αμέσως μετά συμπληρώνουν το ερωτηματολόγιο.
4. Βάλε τις απαντήσεις σε CSV και τρέξε: `python docs/sus_score.py apantiseis.csv`

### Ερωτηματολόγιο (1 = Διαφωνώ απόλυτα … 5 = Συμφωνώ απόλυτα)

| # | Ερώτηση |
|---|---|
| 1 | Νομίζω ότι θα ήθελα να χρησιμοποιώ αυτή την εφαρμογή συχνά. |
| 2 | Βρήκα την εφαρμογή άσκοπα περίπλοκη. |
| 3 | Θεώρησα ότι η εφαρμογή ήταν εύκολη στη χρήση. |
| 4 | Νομίζω ότι θα χρειαζόμουν τη βοήθεια τεχνικού για να μπορέσω να τη χρησιμοποιήσω. |
| 5 | Βρήκα ότι οι διάφορες λειτουργίες της εφαρμογής ήταν καλά ενσωματωμένες. |
| 6 | Θεώρησα ότι υπήρχε πολλή ασυνέπεια στην εφαρμογή. |
| 7 | Φαντάζομαι ότι οι περισσότεροι άνθρωποι θα μάθαιναν να τη χρησιμοποιούν πολύ γρήγορα. |
| 8 | Βρήκα την εφαρμογή πολύ δύσχρηστη. |
| 9 | Ένιωσα πολύ σίγουρος/η χρησιμοποιώντας την εφαρμογή. |
| 10 | Χρειάστηκε να μάθω πολλά πράγματα πριν μπορέσω να ξεκινήσω με την εφαρμογή. |

**Υπολογισμός:** μονές ερωτήσεις → (τιμή − 1), ζυγές → (5 − τιμή), άθροισμα × 2,5.

Πρόσθεσε και 2–3 ανοιχτές ερωτήσεις (π.χ. «Τι σε δυσκόλεψε;», «Ήταν χρήσιμος ο βοηθός;»)
για ποιοτικά σχόλια.

## 4. Πρόταση για αξιολόγηση του AI βοηθού

Φτιάξε 20–30 ερωτήσεις-σενάρια (π.χ. «VIP για Σάββατο απόγευμα κάτω από 15€») και κατέγραψε για καθεμία:
αν απάντησε σωστά με βάση τα δεδομένα, αν πρότεινε έγκυρη κράτηση, πόσα δευτερόλεπτα πήρε.
Το ποσοστό σωστών απαντήσεων και ο μέσος χρόνος είναι καλός πίνακας για την πτυχιακή.
